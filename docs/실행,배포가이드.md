# 실행·배포 가이드

## 1. 구성

| Component | Port / 의존 | 비고 |
| --- | --- | --- |
| nginx | 80, 443 (호스트 노출) | HTTPS 종단, `mobility-expo.duckdns.org` -> `gateway:8080` 리버스 프록시. 업로드 본문 최대 10MB |
| Gateway | 8080 (내부) | `SPRING_PROFILES_ACTIVE=prod`, JWT 검증 + `X-User-*` 주입, CORS. 이미지 경로(`/uploads/**`)도 각 서비스로 라우팅 |
| Identity | 8081 (내부), MySQL `identity` DB, Redis | 가입/로그인/재발급/로그아웃, 소셜 로그인(Google, Kakao, Naver), 비밀번호 재설정 메일, refresh 토큰 HttpOnly 쿠키. Reservation, Expo 호출(회원 탈퇴 시 QR 무효화 등) |
| Expo | 8082 (내부), MySQL `expo` DB, `expo-uploads` 볼륨 | 박람회/부스/신청/상담/차량/리드, Gemini AI 호출, 알림(SSE). Payment, Reservation, Identity 동기 호출 |
| Payment | 8083 (내부), MySQL `payment` DB | 부스 참가비, 당일 입장권 결제/환불, 매출·통계. PortOne 실결제 검증(테스트 채널). Expo, Reservation 동기 호출 |
| Reservation | 8084 (내부), MySQL `reservation` DB | 방문 예약, QR 티켓, 체크인, 입장 통계. Expo, Identity 동기 호출 |
| Review | 8085 (내부), MySQL `review` DB, `review-uploads` 볼륨 | 상담후기, 부스후기, 후기 사진. Expo, Identity 동기 호출 |
| MySQL | 8.0, `mysql-data` 볼륨 | `identity`, `expo`, `payment`, `reservation`, `review` + 각 `_test` DB (`infra/mysql/init/01-databases.sql`) |
| Redis | 7.4, `redis-data` 볼륨 | Identity 전용: refresh 토큰 해시, 이메일 인증 코드, 비밀번호 재설정 토큰, 소셜 가입 보류 정보 |

서비스 간 통신은 compose 네트워크(`backend`) 안에서 서비스명으로만 이뤄지며, 외부에는 nginx(443)만 노출합니다. 서비스 간 호출 주소는 `*_BASE_URL` 환경변수(예: `EXPO_BASE_URL`, `IDENTITY_BASE_URL`)로 주입하고, 기본값은 `localhost` 포트입니다.

- GitHub Actions Secret은 SSH 접속용 `ORACLE_HOST`, `ORACLE_USER`, `ORACLE_SSH_KEY`(이 `ORACLE_*`는 `.env`에서 제외됨)와 **위 표의 모든 앱 환경 변수(키 이름 그대로)**를 등록해야 합니다.
- Vercel 환경 변수는 `VITE_API_BASE_URL` **하나만** 등록합니다.

## 3. 새 clone 로컬 실행

로컬 `docker-compose.yml`은 MySQL, Redis만 띄웁니다. 5개 Service와 Gateway는 Gradle 또는 IDE로 실행합니다.

```bash
cp .env.example .env
docker compose config
docker compose up -d --wait          # mysql, redis
cd backend && ./gradlew test
```

- 로컬에서 서비스를 직접 띄울 때 소셜 로그인 OAuth 값은 `application.yml`에 기본값이 없으므로 IDE 실행 설정 또는 환경 변수로 넣어야 합니다(소셜 로그인을 쓰지 않아도 Identity 기동에는 필요).
- `reservation` 모듈의 `acceptance` 태그 테스트(`Us12SignupAndVisitApplicationAcceptanceTest`)는 Gateway(8080), Identity(8081), Expo(8082), Reservation(8084)이 모두 떠 있어야 하므로 `./gradlew test`에서 제외됩니다. 전체 스택 기동 후 `cd backend && ./gradlew :reservation:acceptanceTest`로 별도 실행합니다.

| 단계 | 명령 / URL | 기대 결과 | 관련 Test | 실제 결과 |
| --- | --- | --- | --- | --- |
| 인프라 기동 | `docker compose up -d --wait` | mysql, redis Health 모두 `healthy` | - | PASS (CI `test` job이 같은 명령으로 기동, [run 35831763447](https://github.com/likelion-backend-24th/Final-Project-Team4/actions/runs/35831763447)) |
| 회귀 Suite | `cd backend && ./gradlew test` | 전체 모듈 `BUILD SUCCESSFUL` | 테스트전략 | PASS ([CI run 35831763447](https://github.com/likelion-backend-24th/Final-Project-Team4/actions/runs/35831763447), dev, PR #314 머지) |
| Gateway 기동 | `./gradlew :gateway:bootRun` | `:8080` 기동 로그(`Started GatewayApplication`) 확인. Actuator는 미포함이라 `/actuator/health`는 없음 | - | NOT_RUN |
| 비회원 조회 Demo | `GET localhost:8080/api/customer/expos` | 200, `data.content` 배열 | `PublicBrowseAcceptanceTest` | 테스트는 CI PASS, 수동 curl은 NOT_RUN |

관리자(`ADMIN`) 계정은 가입 API가 없으며 Identity 기동 시 `ADMIN_EMAIL` / `ADMIN_PASSWORD`로 Seed됩니다. 박람회는 관리자가 등록 후 공개(`OPEN`)해야 비회원 목록에 노출됩니다.

## 4. 운영 배포 (CI/CD)

```
dev 브랜치 push
  -> CI workflow: test(ubuntu) -> build-push(ubuntu-24.04-arm, 6개 이미지 ghcr.io push: gateway, identity, expo, payment, reservation, review)
  -> Deploy workflow: workflow_run(CI, branch=dev)가 success면 실행 (concurrency group `deploy`, 동시 배포 방지)
       appleboy/ssh-action -> Oracle 서버 (set -e)
         cd ~/app
         git pull --ff-only
         umask 077
         GitHub Secrets 전체(ORACLE_* 제외)를 jq로 변환해 .env 생성(덮어쓰기)
         docker compose -f docker-compose.prod.yml pull
         docker compose -f docker-compose.prod.yml up -d
         docker compose -f docker-compose.prod.yml ps
         docker image prune -f
```

- 이미지: `ghcr.io/likelion-backend-24th/team4-<service>:latest` 와 `:<commit-sha>` 두 태그로 push.
- `pull_request` 이벤트는 `test` job만 돌고 이미지 빌드, 배포는 하지 않습니다 (`if: github.event_name == 'push'`).
- CI가 실패하면 `workflow_run` 조건 불충족으로 Deploy는 실행되지 않습니다.
- `frontend/**`, `docs/**`, `*.md`만 바뀐 push는 CI가 실행되지 않아 백엔드 배포도 일어나지 않습니다(`paths-ignore`).
- HTTPS 인증서는 배포 서버 호스트의 certbot이 발급, 갱신합니다. nginx는 `/etc/letsencrypt`(인증서)와 `/var/www/certbot`(ACME webroot)을 읽기 전용으로 마운트합니다. 갱신된 인증서가 nginx에 반영되려면 nginx 재로드(재시작)가 필요할 수 있습니다.

### 서버에서 수동 배포

```bash
cd ~/app
git pull --ff-only
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml ps
docker image prune -f
```

수동 배포 시 `.env`는 마지막 자동 배포가 만든 파일을 그대로 사용합니다. 값을 바꿔야 하면 GitHub Secrets를 수정하고 자동 배포를 다시 돌립니다.

| 검증 | 명령 / URL | 기대 결과 | 실제 결과 |
| --- | --- | --- | --- |
| Compose 구성 | `docker compose -f docker-compose.prod.yml config` | 오류 없음 | PASS |
| 배포 실행 | Deploy workflow (`pull`, `up -d`, `ps`) | `set -e` 하에서 오류 없이 종료 | PASS ([Deploy run 35832100782](https://github.com/likelion-backend-24th/Final-Project-Team4/actions/runs/35832100782), PR #314 CI 성공 후 실행된 배포) |
| 컨테이너 상태 | `docker compose -f docker-compose.prod.yml ps` | mysql, redis `healthy`, 나머지 `Up` | NOT_RUN (Deploy run은 `ps` 명령의 종료 코드만 확인) |
| HTTPS 진입 | `curl -i <https://mobility-expo.duckdns.org/api/customer/expos`> | 200, `Access-Control-Allow-Origin` 헤더 포함 | PASS (빈 목록 `{"content":[],"totalElements":0}`) |
| CORS preflight | `curl -X OPTIONS -H "Origin: <https://mobility-expo.vercel.app>" ...` | 204, `Access-Control-Allow-Origin` 일치 | NOT_RUN |
| Secret 노출 | 로그, 응답 본문 | 실제 키/토큰/쿠키 값 없음 | 없음 |

## 6. 중지 / 재기동 / 데이터 초기화

| 작업 | 명령 | 영향 / 복구 |
| --- | --- | --- |
| 전체 중지 | `docker compose -f docker-compose.prod.yml down` | 컨테이너 제거, `mysql-data` / `redis-data` / `expo-uploads` / `review-uploads` 볼륨 유지. `up -d`로 복구 |
| 단일 재기동 | `docker compose -f docker-compose.prod.yml restart gateway` | 해당 컨테이너만 재시작, 데이터 영향 없음 |
| 이미지 갱신 재배포 | `... pull && ... up -d` | 새 이미지로 교체, MySQL 데이터와 업로드 파일 유지 |
| **전체 데이터 초기화** | `docker compose -f docker-compose.prod.yml down -v` | `mysql-data`, `redis-data`, `expo-uploads`, `review-uploads` 볼륨 삭제. **모든 데이터(회원, 결제, 박람회 배너, 차량 이미지, 후기 사진 포함) 소실, 복구 불가.** 재기동 시 `infra/mysql/init` 재실행, 관리자 Seed 재생성 |
| Payment 데이터 | `mysql` 컨테이너의 `payment` DB | Payment도 MySQL에 영구 저장되므로 재기동만으로는 초기화되지 않음. 초기화하려면 위 `down -v` 사용 |
| Redis 데이터만 삭제 | `docker volume rm car-expo-prod_redis-data` (전체 중지 후) | 모든 사용자의 refresh 토큰이 사라져 재로그인 필요. 진행 중인 이메일 인증, 비밀번호 재설정, 소셜 가입 보류도 무효화 |

## 7. 알려진 이슈

- **배포 직후 짧은 5xx**: `docker-compose.prod.yml`의 gateway `depends_on`이 `condition: service_healthy`를 걸지 않아, Expo 기동(약 30~40초) 전에는 `/api/customer/expos` 등이 502/500을 반환합니다. 잠시 후 재시도하면 정상. CORS 헤더 없는 500이라 브라우저 콘솔에는 CORS 오류로 표시될 수 있습니다.
- **서비스 간 호출 주소 확인 필요**: `docker-compose.prod.yml`이 명시적으로 넣는 `*_BASE_URL`은 서비스별로 일부뿐입니다(예: Expo는 `IDENTITY_BASE_URL`이, Identity는 `RESERVATION_BASE_URL`, `EXPO_BASE_URL`이 compose에 없음). 이 값들은 코드 기본값이 `localhost`라서, `.env`(GitHub Secrets)로 주입되지 않으면 컨테이너 안에서 다른 서비스를 찾지 못합니다. 영향 기능: 참가업체 회사명 조회, 리드 이메일 발송(Expo -> Identity), 회원 탈퇴 시 입장권 QR 무효화(Identity -> Reservation). 운영에서 이 기능들이 동작하는지 확인하거나, compose `environment`에 서비스명 주소를 추가해야 합니다.
- **Actuator 미포함**: 모든 서비스에 `spring-boot-starter-actuator`가 없어 `/actuator/health` 헬스체크는 사용할 수 없습니다(compose 헬스체크는 MySQL, Redis에만 있음).
