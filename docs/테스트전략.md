## 테스트 수준 정의

| 수준 | 범위 | 대표 도구 |
| --- | --- | --- |
| Unit | 단일 도메인 규칙·상태 전이(협력자 없음 또는 Mock) | JUnit 5 |
| Component | 한 Service 안에서 HTTP 진입점 ~ DB까지(다른 Service는 Stub) | MockMvc, MySQL(로컬/CI 컨테이너) |

## 테스트 데이터·격리·복구 규칙

- Fixture ID는 `sprint-story-scenario-sequence` 형식으로 이름을 통일한다(예: `s1-story2-normal-01`).
- 각 Test는 자신이 만든 사용자·박람회·신청·결제·자리·매출 데이터만 사용하고, 실행 전후 같은 초기 상태를 재현한다(`@BeforeEach`에서 관련 테이블 정리, 실행 순서에 의존 금지).
- Mock 외부 응답(사업자 인증·Mock 결제)과 `Idempotency-Key`·내부 토큰은 Test 안에서 고정한다.
- 응답 유실·같은 Key 재호출·서로 다른 Key 경쟁은 **최초 처리 결과와 재처리 결과를 함께** 검증한다.
- 격리·복구에 실패한 Test는 재실행으로 숨기지 않고 실패 Evidence와 원인을 해당 Story Issue에 남긴다.
- 로컬 Flyway 체크섬 불일치는 `DROP DATABASE`가 아니라 `flyway repair` 또는 `.gitattributes`(`.sql text eol=lf`)로 해결한다.

## 원칙

- 상태 어휘는 `PASS` / `FAIL` / `NOT_RUN`만 사용하고, 실행 사실과 Evidence가 있을 때만 `PASS`/`FAIL`로 기록한다.
- 모든 인증 실패 응답에 `WWW-Authenticate: Bearer`가 있는지, 비밀번호 원문·Hash·토큰이 응답·일반 Log에 없는지 매 Sprint 회귀에서 확인한다.
- 서비스 간 호출 Test는 연결·응답 Timeout과 fail-closed 동작(권한·거래를 성공으로 열지 않음)을 반드시 포함한다.
- 상태 변경 계약은 멱등 재요청 Test 없이 완료로 판정하지 않는다.
- 계약·시퀀스가 바뀌면 `openapi.yaml` → API.md → 시퀀스 → 이 문서 순으로 갱신하고, 영향받는 Test 이름을 함께 수정한다.
