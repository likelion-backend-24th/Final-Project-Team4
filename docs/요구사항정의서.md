# 요구사항 정의서

## **1. 사용자 문제·Product Goal·성공 기준**

| **항목** | **정의** |
| --- | --- |
| 사용자 문제 | 참가업체는 담당 부스를 운영하며 예약·입장·정산을 각각 수기로 처리하느라 데이터가 분산되고 시간이 낭비되며, 참가자는 박람회마다 다른 예약 절차를 거치고 현장에서 명단 대조로 입장이 지연되는 불편을 겪는다. |
| Product Goal | 방문객이 자동차 박람회 정보를 확인하고 예약, 결제, 입장까지 하나의 서비스를 편리하게 이용할 수 있도록 한다. 참여 관리자에게는 차량 및 브랜드를 홍보하여 잠재 고객과 연결할 수 있는 기회를 제공하고,  관리자는 박람회에서 홍보, 예약, 결제, 입장 현황을 정확하고 효율적으로 관리할 수 있는 환경을 제공한다. |

### **Release 성공 기준**

- 동일한 결제·환불 요청이 반복되어도 거래와 매출 원장에는 한 번만 반영되며, 결제·환불·참가 확정·입장권 상태의 일관성이 유지된다.
- 권한 실패, 중복 요청, Mock 결제 응답을 확인하지 못한 상황에서도 콘텐츠·거래·정산 상태를 안전하게 유지한다.
- 동일 거래에 대한 동시 요청이 들어와도 하나만 성공 처리되고, 나머지는 안전하게 거부되거나 동일한 결과를 반환한다.
- 같은 부스 자리에 동시에 여러 확정 요청이 들어와도 정확히 1건만 배정되고, 한 자리가 두 업체에게 확정되는 경우는 없다.
- 박람회 매출 현황과 결제·환불 통계는 항상 매출 원장과 정확히 일치하고(집계 오차 없음), 데이터가 많아져도 조회 응답이 정해진 시간 안에 끝난다.
- 참가업체는 자신이 속하지 않은 박람회나 담당하지 않는 부스의 신청·매출·콘텐츠 데이터에 접근할 수 없다. 권한 없는 API 호출은 차단되어 감사 로그에 남고, 만료된 세션·토큰 요청은 재인증을 요구한다.

## **2. 대상 사용자·Release 범위**

### **대상 사용자**

| **Actor** | **목표·책임** |
| --- | --- |
| 방문자(비회원) | 회원가입 전 박람회 목록·상세와 참여 브랜드·차량 정보, 참가업체 공개 게시글을 조회한다. |
| 고객(회원) | 이메일로 회원가입·로그인해 박람회 세부 정보와 후기를 조회하고, 무료 입장권을 발급받거나 당일 입장권을 결제해 입장하며, 부스에 상담·시승을 신청한다. |

| 관리자 | 플랫폼 전체를 운영한다. 박람회와 부스를 등록·공개하고, 부스 신청을 심사(승인·반려)하며, 현장 입장(체크인)과 입장 현황을 관리하고, 박람회별 매출 현황과 결제·환불 통계를 확인한다. |
