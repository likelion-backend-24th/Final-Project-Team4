### 서비스가 아닌 것

- SMS: 상태 전이 후 로그로만 남긴다. (예외: 비밀번호 재설정 메일은 Identity가 `MailSender`로 발송, `app.mail.provider=log`이면 링크만 로그 출력. 리드 이메일 발송도 같은 `MailSender` 재사용해 실제 발송함)
- 알림(이메일 제외)은 서비스가 아닌 것이 아니라 **Expo 책임으로 구현됨** — `notifications` 테이블, SSE 스트림, 읽음처리 API(exhibitor/customer 양쪽). 로그로만 남기는 단계 지남.
- 실제 PG·계좌·송금·외부 회계: 제외 범위. Payment 내부 Mock 어댑터로 대체.
- 정산 리포트·참가업체 지급(송금), VIP 배너 광고, 부분 환불: 후속 Product Backlog(US-B1~US-B6). (전액 환불은 이미 구현됨 — 부분 환불만 백로그)

## **데이터 소유권**

| **데이터** | **소유 Service** | **생성·변경 책임** | **다른 Service 참조 방법** | **직접 DB 접근** |
| --- | --- | --- | --- | --- |
| `User` (Role = `users.role` enum) | Identity | Identity만 생성·변경 | JWT Claim(`sub`·`role`) -> Gateway가 `X-User-Id`·`X-User-Role` 주입. 회사·담당자 정보·고객 이름 조회는 `GET /internal/identity/users/{userId}`, 메일발송은 `POST /internal/identity/mails` | 금지 |
| `Expo`, `Booth`, `BoothApplicationGroup`, `BoothApplication`, `Post`, `Vehicle`, `VehicleImage`, `Consultation`, `ConsultationSlotCapacity`, `Lead`, `Notification` | Expo | Expo만 생성·변경 | 공개·내부 API와 `expoId`·`boothId`·`groupId`·`applicationId`·`leadId` 논리 참조 | 금지 |
| `Ticket`, `CheckIn` | Reservation | Reservation만 생성·변경 | `ticketId`, `customerId`(= userId), `expoId` + 내부 API(`admission-context`, `tickets/{visitDate}`, `tickets/resolve` 등) | 금지 |
| `Payment`, `PaymentItem`, `AdmissionPayment`, `AdmissionPaymentTicket` | Payment | Payment만 생성·변경 | `paymentId`, `bookingId` + Payment 조회 API(`GET /{bookingId}/status`) | 금지 |
| `Review`, `ReviewImage` | Review | Review만 생성·변경 | `reviewId` + Review 조회 API, 자격 확인은 Expo 내부 API(`review-eligibility`)로 역참조 | 금지 |
- 다른 Service의 ID는 논리 참조이며 FK를 걸지 않는다.
- 부스 참가비·당일 입장 금액은 결제 시점 Snapshot으로 고정한다. 환불은 `AdmissionPaymentTicket.refundedAt`/`refundReason` 필드로 이미 기록되며(구현완료), append-only 매출 원장 방식의 별도 `RevenueLedgerEntry` 테이블은 아직 없음 — 현재 매출·통계(`PaymentStatsController`/`RevenueController`)는 결제 테이블 집계 조회로 구현됨.
- 개인정보(연락처·이메일)는 소유 Service에서 저장 시 암호화하고, 권한 없는 조회를 차단하며 시도를 감사 로그에 남긴다.

- 내부 계약(`Expo<->Identity`, `Reservation<->Expo`, `Payment<->Reservation`, `Payment<->Expo`, `Review<->Expo`, `Review<->Identity`)은 Gateway에 Route하지 않는다.
- 각 내부 호출은 호출 관계별 환경 변수 Bearer Token(SVC_TOKEN)으로 허용 Service만 검증하고, Gateway가 만든 Trace ID를 모든 동기 호출·로그에 전파한다.
- 결제·환불·발급처럼 상태를 바꾸는 내부 호출은 Idempotency-Key(PUT 성격)로 중복 요청 시 동일 결과를 반환한다.

다른 Service DB 조회·JOIN·갱신은 허용하지 않습니다. 이후 Sprint 계약은 위험을 확인하기 전까지 `PLANNED`로 둡니다.
